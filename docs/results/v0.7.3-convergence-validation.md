# v0.7.3 Convergence Validation (Targeted False-Outcome Fixes)

This is a sanitized record of a targeted validation run after three review-layer improvements aimed at the five non-success cases from the v0.7.3 full curated benchmark. It is a single stochastic repetition over those five cases; it is not a multi-repetition qualification or a claim about production reliability.

## What changed since the full benchmark

Three review-layer changes target the documented false accepts and the false reject:

- **Reviewer transient-error retry.** Semantic reviewer model calls now retry transient generation errors (configurable `semantic_review.max_model_retries`, default 2, with a short linear backoff) before failing closed. A single API hiccup no longer discards an otherwise correct candidate; only an exhausted retry budget is recorded as a model error.
- **Wider, resolvable delimiter cue.** The deterministic `delimiter_composition` cue now also fires on a regex normalization that inserts a delimiter excluded from its own negated character class — the classic `re.sub("[^a-z0-9-]+", "-", text)` slugify bug, where pre-existing separators survive and repeat. The cue clears once repeated delimiters are collapsed (for example a follow-up `re.sub("-+", "-", ...)`) or the class no longer excludes the delimiter (`re.sub("[^a-z0-9]+", "-", ...)`).
- **Reviewer domain conventions.** The reviewer prompt now carries explicit conventions to verify against the task wording and supplied evidence: banker's rounding (`decimal.ROUND_HALF_EVEN`) for proration or tie-breaking versus `ROUND_HALF_UP` for currency/tax/invoice display; collapsing repeated separators in slugs; rejecting non-positive configuration-style parameters (delays, timeouts, retries, sizes, counts); and raising on traversal cycles rather than silently stopping. Each is evidence-gated; a blocking risk is reported only when the task/domain requires the convention and the candidate visibly violates it.

The numeric rounding cue was deliberately left unchanged. Widening it to flag non-banker's modes would also fire on `decimal_invoice` and `demo_project`, whose correct solutions legitimately use `ROUND_HALF_UP`. Rounding-mode correctness is domain semantics that a static cue cannot decide without the holdout specification.

## Interpretation

The three fixes land where the diagnosis predicted. The false reject and the two cue/convention-addressable false accepts are resolved; `multifile_retry` exercises the full deterministic chain (cue → forced revision → guard added → cue cleared → accepted). The two remaining false accepts are precisely the domain-semantic cases: the reviewer now engages `multifile_token_rotation` (it demands a revision instead of accepting outright) but the candidate stops short of the holdout's exact raise contract, and `multifile_proration` hinges on a rounding-mode convention that is invisible without the holdout. This is the test-driven-repair information gap, not a defect introduced by these changes.

This is one stochastic repetition; the `slugify` and `multifile_token_rotation` outcomes carry model nondeterminism, and a repeated run would tighten these figures. The raw machine-readable report remains a local experiment artifact under `outputs/benchmarks/`.
